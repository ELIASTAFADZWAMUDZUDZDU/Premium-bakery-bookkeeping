# Premium Bakery Bookkeeping — System Documentation

Technical reference for the workbook generated by `src/build_workbook.py`. Covers every sheet, every formula, named ranges, data validation, and chart data sources.

File: `templates/Premium_Bakery_Bookkeeping_TEMPLATE.xlsx`

---

## 1. Sheet map

| Sheet | Purpose | Edited manually? |
|---|---|---|
| `How To Use` | Quick-start instructions | No |
| `Dashboard` | KPIs, today's live view, this-month view, this-year view, quick facts, 4 charts | No |
| `Income` | Log of every sale/order | **Yes — primary data entry** |
| `Expenses` | Log of every purchase/cost | **Yes — primary data entry** |
| `Daily Report` | Day-by-day breakdown for one selected month | No (except Month/Year selectors) |
| `Monthly Summary` | Month-by-month + category-by-category rollups for one selected year | No (except Year selector) |
| `Yearly Report` | Fixed 2024–2040 multi-year history | No (no selector — always shows every year) |
| `Categories` | Dropdown source lists | Only when categories change |

Data flow: `Income` / `Expenses` → `Daily Report`, `Monthly Summary`, `Yearly Report` → `Dashboard`. The two log sheets are the only source of truth; every other sheet is a formula layer.

---

## 1a. Sheet protection

Every sheet except `Income`, `Expenses`, and `Categories` is fully locked against editing. No password is set anywhere — this prevents accidental edits, not deliberate ones; anyone with edit access to the file can remove protection via Google Sheets' "Protect sheets and ranges" or Excel's "Unprotect Sheet".

| Sheet | Protected? | Editable cells |
|---|---|---|
| `Income` / `Expenses` | Yes | Rows 4–5002, columns A–F (the example row + all data rows). Headers (rows 1–3) and the total row (5003) are locked. |
| `Daily Report` | Yes | `H2` (Month) and `J2` (Year) only |
| `Monthly Summary` | Yes | `H2` (Year) only |
| `Yearly Report` | Yes | None — no selector, so nothing is left open |
| `Dashboard` / `How To Use` | Yes | None |
| `Categories` | **No** | Entire sheet — intentional, occasional edits (adding/renaming a category) shouldn't require unprotecting first |

Protection is set in the generator script via `lock_whole_sheet()` / `protect_with_unlocked_cells()` / `unlock_range()` (see `src/build_workbook.py`). Excel-style protection from `openpyxl` does not always survive a Google Sheets import cleanly — verify after importing, and fall back to Google Sheets' own **Data → Protect sheets and ranges** with the same boundaries above if it doesn't carry over.

## 2. Income & Expenses — layout

Both sheets use an identical 6-column layout:

| Column | Field | Notes |
|---|---|---|
| A | Date | Must be a real date value, not text — see §6 |
| B | Description | Free text |
| C | Category | Dropdown, sourced from `Categories` |
| D | Payment Method | Dropdown, sourced from `Categories` |
| E | Amount (R) | Numeric |
| F | Notes | Free text, optional |

**Row map (identical on both sheets):**

| Row | Contents |
|---|---|
| 1 | Sheet title banner |
| 2 | Instruction subtitle |
| 3 | Column headers |
| 4 | Example row (yellow highlight) — sample data |
| 5–5002 | Data entry rows (~5,000-row capacity, ~13+ years of daily use) |
| 5003 | Total row — `=SUM(E4:E5002)` in column E |

If the log ever approaches row 5002, insert new rows **above** row 5003 (the total row) so that every formula referencing `$A$4:$A$5002` / `$E$4:$E$5002` throughout the workbook continues to include the new rows. Spot-check the total row after doing so.

A large fixed range was used instead of an open-ended whole-column reference (`C5:C`) because the workbook is built by a script that pre-formats every data row (currency format, date format, borders, dropdown validation) — a static file cannot format an unbounded range. A large fixed cap gives effectively the same headroom without leaving unformatted rows beyond it.

## 3. Dropdowns (data validation)

Data validation on `Income!C5:C5002` / `Expenses!C5:C5002` (Category) and `Income!D5:D5002` / `Expenses!D5:D5002` (Payment Method) reference three named ranges on the `Categories` sheet:

| Named range | Refers to | Used for |
|---|---|---|
| `IncomeCatList` | `Categories!$A$2:$A$20` | Income → Category dropdown |
| `ExpenseCatList` | `Categories!$B$2:$B$20` | Expenses → Category dropdown |
| `PaymentList` | `Categories!$C$2:$C$20` | Payment Method dropdown (both sheets) |

Default categories:

- **Income**: Custom Orders, Catering Orders, Wholesale Orders, Online Orders, Delivery Charges Collected, Other Income
- **Expenses**: Raw Materials / Ingredients, Packaging & Boxes, Rent, Electricity & Water, Salaries & Wages, Equipment & Maintenance, Marketing & Promotion, Transport & Delivery, Licence & Compliance, Cleaning & Supplies, Other Expenses
- **Payment Methods**: Cash, Card, EFT / Bank Transfer, Other

To add or rename a category, edit the `Categories` sheet directly — the named ranges cover rows 2–20, so new rows within that range are picked up automatically by the dropdowns.

**Renaming caveat**: `Monthly Summary` rows 21–31 (expense categories) and 21–26 (income categories) reference category names as literal text, copied at generation time. Renaming a category in `Categories` after the fact does not automatically update these labels — update them manually, or regenerate the workbook from `src/build_workbook.py`.

## 4. Daily Report — formula reference

Selectors: `Daily Report!H2` (Month, 1–12) and `Daily Report!J2` (Year). Every formula on this sheet reads from these two cells.

**Row 4**: headers — Day, Date, Total Income, Total Expenses, Net Profit, Transactions.

**Rows 5–35** (31 possible day rows, one per calendar day):

```
A (Day)          static integer 1–31
B (Date)         =IF(A<row>≤DAY(EOMONTH(DATE($J$2,$H$2,1),0)), DATE($J$2,$H$2,A<row>), "")
C (Income)       =IF($B<row>="","",SUMIFS(Income!$E$4:$E$5002, Income!$A$4:$A$5002, $B<row>))
D (Expenses)     =IF($B<row>="","",SUMIFS(Expenses!$E$4:$E$5002, Expenses!$A$4:$A$5002, $B<row>))
E (Net Profit)   =IF($B<row>="","",C<row>-D<row>)
F (Transactions) =IF($B<row>="","",COUNTIFS(Income!$A$4:$A$5002,$B<row>)+COUNTIFS(Expenses!$A$4:$A$5002,$B<row>))
```

The `IF(A≤DAY(EOMONTH(...)),...,"")` check means rows for days that don't exist in the selected month (e.g. day 30 in February) render blank rather than showing a zeroed/incorrect date, and their Income/Expenses/Profit/Transactions cells blank out in turn since they key off column B being empty.

**Row 36 — Month Total**: `=SUM(C5:C35)` / `=SUM(D5:D35)` / `=SUM(E5:E35)` / `=SUM(F5:F35)`. Text ("") in blank day rows is ignored by `SUM`.

This sheet only reflects **one month at a time** (whatever is in H2/J2) — it is not a running log across months.

## 5. Monthly Summary — formula reference

Year selector: `Monthly Summary!H2`. Every formula on this sheet reads from `$H$2`.

**Monthly rows (4–15, Jan → Dec):**

```
B (Total Income)    =SUMIFS(Income!$E$4:$E$5002, Income!$A$4:$A$5002, ">="&DATE($H$2,<month>,1), Income!$A$4:$A$5002, "<"&DATE($H$2,<month>+1,1))
C (Total Expenses)  = same pattern, reading from Expenses!$E$4:$E$5002
D (Net Profit)       =B<row>-C<row>
E (Profit Margin %) =IFERROR(D<row>/B<row>,0)
F (Transactions)    =COUNTIFS(...) on Income + COUNTIFS(...) on Expenses, added together
```

**Row 16 — Year Total**: sums rows 4–15 for columns B, C, D, F; margin recomputed as `D16/B16`.

**Rows 19–31 — category breakdown tables** (feed the two Dashboard pie charts):

- **Expenses by category**: labels `A21:A31` (11 rows), amounts `B21:B31`, each a `SUMIFS` against `Expenses!$C$4:$C$5002` (category match) plus a year filter on `Expenses!$A$4:$A$5002`.
- **Income by category**: labels `D21:D26` (6 rows), amounts `E21:E26`, same pattern against `Income!$C$4:$C$5002`.

Both breakdown tables reflect **one year at a time** — not all-time totals.

## 5a. Yearly Report — formula reference

No selector — this sheet always shows the fixed span **2024–2040** (17 rows, `A4:A20`), one row per year.

```
B (Total Income)    =SUMIFS(Income!$E$4:$E$5002, Income!$A$4:$A$5002, ">="&DATE(<year>,1,1), Income!$A$4:$A$5002, "<"&DATE(<year>+1,1,1))
C (Total Expenses)  = same pattern, reading from Expenses!$E$4:$E$5002
D (Net Profit)      =B<row>-C<row>
E (Profit Margin %) =IFERROR(D<row>/B<row>,0)
F (Transactions)    =COUNTIFS(...) on Income + COUNTIFS(...) on Expenses, added together
```

**Row 21 — All Years Total**: sums rows 4–20 for columns B, C, D, F; margin recomputed as `D21/B21`.

To extend the range beyond 2040, edit `YEARLY_YEARS = list(range(2024, 2041))` in `src/build_workbook.py` and regenerate.

## 6. Dates — why they matter everywhere

Every "today," "this month," and "this year" calculation depends on column A actually holding a date value, not text that merely looks like one. A pasted or unusually-formatted entry can silently drop out of every SUMIFS/COUNTIFS calculation with no error shown — it just won't appear in any total.

Quick check: date values are right-aligned by default; text is left-aligned. A left-aligned entry in column A is stored as text and needs to be re-entered as a real date.

## 7. Dashboard — cell reference map

KPI cards are built with a helper function that merges each card into a 2-column block; the **formula lives in the top-left cell of the merged value block**, not necessarily where a click lands centered.

| Card | Label | Value cell | Formula |
|---|---|---|---|
| Total Income | row 7 | **A8** | `=Income!E5003` |
| Total Expenses | row 7 | **C8** | `=Expenses!E5003` |
| Net Profit | row 7 | **E8** | `=A8-C8` |
| Profit Margin | row 7 | **G8** | `=IFERROR(E8/A8,0)` |
| Income Today | row 13 | **A14** | `=SUMIFS(Income!$E$4:$E$5002,Income!$A$4:$A$5002,TODAY())` |
| Expenses Today | row 13 | **C14** | `=SUMIFS(Expenses!$E$4:$E$5002,Expenses!$A$4:$A$5002,TODAY())` |
| Profit Today | row 13 | **E14** | `=A14-C14` |
| Income This Month | row 19 | **A20** | `SUMIFS` on `Income!$E$4:$E$5002` between the 1st of the current month and the 1st of next month |
| Expenses This Month | row 19 | **C20** | same pattern on `Expenses!$E$4:$E$5002` |
| Profit This Month | row 19 | **E20** | `=A20-C20` |
| Orders This Month | row 19 | **G20** | `COUNTIFS` on `Income!$A$4:$A$5002` for the current month |
| Income This Year | row 25 | **A26** | `SUMIFS` on `Income!$E$4:$E$5002` between 1 Jan and 1 Jan next year of the current year |
| Expenses This Year | row 25 | **C26** | same pattern on `Expenses!$E$4:$E$5002` |
| Profit This Year | row 25 | **E26** | `=A26-C26` |
| Orders This Year | row 25 | **G26** | `COUNTIFS` on `Income!$A$4:$A$5002` for the current calendar year |
| Best-selling category (this year) | row 31 | **B31** | `INDEX/MATCH` against `Monthly Summary!D21:D26` / `E21:E26` |
| Biggest expense category (this year) | row 32 | **B32** | `INDEX/MATCH` against `Monthly Summary!A21:A31` / `B21:B31` |
| Average order amount (all time) | row 33 | **B33** | `=IFERROR(Income!E5003/COUNT(Income!E4:E5002),0)` |
| Biggest single order (all time) | row 34 | **B34** | `=IFERROR(MAX(Income!E4:E5002),0)` |

**"Today" and "This Month" both re-evaluate on `TODAY()`** — no manual updating required. "Today" uses an exact date match (`SUMIFS(...,TODAY())`); "This Month" uses a `DATE(YEAR(TODAY()),MONTH(TODAY()),1)` to `EDATE(...,1)` range.

### Today's Live View — chart data source

The "Today: Income vs Expenses" bar chart does not read from Income/Expenses directly — it reads from a small two-row helper table placed off to the side of the main layout (columns K/L, rows 13–14), so the chart has a clean, fixed data range to bind to:

```
K13: "Income"      L13: =A14   (mirrors Income Today)
K14: "Expenses"    L14: =C14   (mirrors Expenses Today)
```

This table is intentionally styled in a muted, low-contrast font — it's a chart data source, not a card meant to be read directly (the KPI cards above it show the same numbers legibly).

### Chart data sources (all four)

| Chart | Anchor | Data source |
|---|---|---|
| Today: Income vs Expenses (bar) | `I11` | `Dashboard!L13:L14` (values), `Dashboard!K13:K14` (categories) |
| Monthly Income vs Expenses (bar) | `A37` | `Monthly Summary!B3:C15` (values), `A4:A15` (month labels) |
| Net Profit Trend (line) | `A55` | `Monthly Summary!D3:D15` |
| Expenses by Category (pie) | `I37` | `Monthly Summary!B20:B31` |
| Income by Category (pie) | `I55` | `Monthly Summary!E20:E26` |

If a chart looks empty or wrong after an edit, check that these source ranges on `Monthly Summary` / `Dashboard` haven't shifted (e.g. from inserting or deleting rows in the category tables).

## 8. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| A row's amount isn't reflected in any total | Date stored as text, not a real date | Re-enter the date; check left- vs right-alignment |
| Dropdown missing a newly added category | Category added outside rows 2–20 on `Categories` | Keep new categories within row 20, or extend the named range |
| Pie chart shows an old category name | Category renamed on `Categories` but not on `Monthly Summary` breakdown table | Manually update the matching label in `Monthly Summary!A21:A31` (expenses) or `D21:D26` (income), or regenerate the workbook |
| "This year" figures look wrong or empty | `Monthly Summary!H2` doesn't match the year being logged | Change `H2` |
| "Daily Report" shows the wrong month | `Daily Report!H2` / `J2` not set to the intended month/year | Change `H2` (month) / `J2` (year) |
| "Yearly Report" doesn't show a year I need | Year falls outside the fixed 2024–2040 span | Edit `YEARLY_YEARS` in `src/build_workbook.py` and regenerate |
| Can't type in a sheet other than Income/Expenses | Sheet protection working as intended | Only Income, Expenses, and the Month/Year selector cells on Daily Report / Monthly Summary are meant to be editable; Categories is also open. Everything else is deliberately locked — see §1a |
| Totals stop updating after adding rows | New rows added past row 5002, outside the formula ranges | Insert new rows above row 5003 rather than appending after it, or extend `DATA_ROWS_END` and regenerate |
| Import into Google Sheets shows blank charts briefly | Named ranges/charts sometimes need a moment to rebuild on first open | Reload the sheet; if it persists, check Data → Named ranges still lists the three ranges from §3 |

## 9. Regenerating the workbook

The workbook is generated by `src/build_workbook.py` using `openpyxl`, not built by hand. Structural changes (new column, different row capacity, new sheet, rebranded colors) should go through the script and a regeneration rather than direct editing of the `.xlsx`, since the script keeps every formula range, named range, and chart reference in sync automatically.

Key constants in the script:

- `DATA_ROWS_END = 5002` — controls the ~5,000-row capacity of `Income` / `Expenses`. Raising this requires the formula ranges throughout `Daily Report`, `Monthly Summary`, `Yearly Report`, and `Dashboard` to be regenerated (the script already parameterizes these off `DATA_ROWS_END`, so a single value change and rerun handles it).
- `YEARLY_YEARS = list(range(2024, 2041))` — the fixed year span shown on `Yearly Report`. Extend the range and regenerate to cover more years.
- `income_categories`, `expense_categories`, `payment_methods` — plain Python lists; editing and rerunning keeps `Categories`, the dropdowns, and the `Monthly Summary` breakdown tables in sync (safer than hand-editing per §3's renaming caveat).
- `CURRENCY_FMT = '"R"#,##0'` — South African Rand, no decimals.
- `lock_whole_sheet()`, `protect_with_unlocked_cells()`, `unlock_range()` — the sheet-protection helpers described in §1a. No password is set.

```bash
pip install -r requirements.txt
python src/build_workbook.py
```

Regenerates `templates/Premium_Bakery_Bookkeeping_TEMPLATE.xlsx` from scratch.

# Premium Bakery — Bookkeeping System

A self-updating income/expense tracker and KPI dashboard for a small bakery, built as a Google Sheets / Excel workbook.

---

## What it does

Every sale and every expense gets logged once, in one row, on one of two tabs. Everything else — daily totals, monthly reports, category breakdowns, KPIs, and charts — is calculated automatically from those two logs. There is no manual math, no separate reporting step, and nothing to remember to update.

Currency: South African Rand (R).

---

## How data flows through the system

```
 Income tab  ──┐
               ├──▶  Daily Report   ──▶  Monthly Summary  ──▶  Yearly Report  ──▶  Dashboard
 Expenses tab ─┘     (day-by-day)        (month-by-month,       (year-by-year)      (KPIs + charts)
                                          category-by-category)
```

Only **Income** and **Expenses** are ever edited by hand. Every other sheet is a formula layer reading from those two — change a number in Income or Expenses, and it ripples forward automatically to the daily report, the monthly report, the yearly report, and the dashboard.

Sheet protection enforces this: Income, Expenses, and Categories are the only sheets open for typing (Daily Report and Monthly Summary each leave just their Month/Year selector cell open). Everything else is locked to prevent accidental edits.

## Sheets

| Sheet | Purpose | Manually edited? |
|---|---|---|
| **How To Use** | Plain-language quick-start guide | No |
| **Dashboard** | All-time KPIs, a live "today" view, this-month KPIs, this-year KPIs, quick facts, and 4 charts | No |
| **Income** | Log of every sale/order (date, description, category, payment method, amount, notes) | **Yes** |
| **Expenses** | Log of every purchase/cost (same layout as Income) | **Yes** |
| **Daily Report** | Day-by-day income/expense/profit breakdown for one selected month | No (except the Month/Year selector) |
| **Monthly Summary** | Month-by-month and category-by-category rollups for one selected year; feeds the Dashboard charts | No (except the Year selector) |
| **Yearly Report** | Fixed 2024–2040 multi-year history, one row per year | No (no selector — always shows every year) |
| **Categories** | The lists behind the Category and Payment Method dropdowns | Only if categories change |

Both log sheets share the exact same 6-column layout (Date, Description, Category, Payment Method, Amount, Notes) on purpose — one layout to learn, not two. Each has capacity for roughly 5,000 entries (~13+ years of daily use).

See [`docs/SYSTEM_DOCUMENTATION.md`](docs/SYSTEM_DOCUMENTATION.md) for the full formula-by-formula reference, and [`docs/WORKBOOK_STRUCTURE.md`](docs/WORKBOOK_STRUCTURE.md) for a plain sheet/cell map.

## Getting started

1. Open [Google Sheets](https://sheets.google.com) → **File → Import → Upload**.
2. Upload `templates/Premium_Bakery_Bookkeeping_TEMPLATE.xlsx`.
3. Choose "Insert new sheet(s)" (or "Replace spreadsheet" if starting fresh).
4. Start on the **How To Use** tab for the 5-step walkthrough.
5. Each log sheet has one yellow example row — overwrite it with a real entry, or delete it.

```
├── requirements.txt                   — Python dependency (openpyxl)

│   └── WORKBOOK_STRUCTURE.md          — condensed sheet/row/column structure overview

│   └── build_workbook.py              — the script that generates the workbook
└── templates/
    └── Premium_Bakery_Bookkeeping_TEMPLATE.xlsx   — the blank template (no real data)
```

**Important**: `templates/` holds a template only — structure, formulas, and formatting, with one fictional example row per log sheet. It never contains real business data. A working copy that gets filled in with actual sales and expenses should be kept separately (Google Sheets/Drive) and is excluded from version control via `.gitignore`.

## Regenerating the workbook

The template is generated by a Python script, not built by hand — this makes structural changes (adding a column, changing row capacity, adding a category) far less error-prone than editing the `.xlsx` directly, since the script keeps every formula range in sync.

```bash
pip install -r requirements.txt
python src/build_workbook.py
```

This regenerates `templates/Premium_Bakery_Bookkeeping_TEMPLATE.xlsx` from scratch.
